# 文件处理与外部调用

Agent 在沙箱外读取 Skill、决定步骤并调用模型和第三方 API；沙箱执行代码、处理文件、回传结果。真实 API Key 留在 Agent 后端的连接器，不注入沙箱。当前接口仍为内网免认证 gRPC。

## 本次提供什么

| 内容 | 行为与边界 |
|---|---|
| 文件类型识别 | PDF、PNG、JPEG、WebP 检查文件头并实际解析；Word/Excel 检查 ZIP 内部结构。扩展名与识别类型冲突时失败。没有扩展名的上述二进制文件也可识别 |
| 文本类型 | TXT、CSV 没有唯一的文件头，按扩展名进行 UTF-8 内容校验和格式解析；JSON 必须能解析。不是通用 MIME 检测或病毒检测 |
| 图片规范化 | 支持单帧 PNG/JPEG/WebP，校正 EXIF 方向，保留透明度，按比例缩小，不放大；输出 `normalized.png`，移除 EXIF、ICC、文本等输入元数据。最多 1600 万像素、单边最多 16384 像素，动图明确失败 |
| PDF 转图 | 默认仍只提取文字；指定 `pdf_images` 后额外输出 `page-001.png` 等，最多 7 页，页数超过请求上限时失败，不丢页。加密 PDF 不支持；不执行 PDF JavaScript、不联网、不做 OCR |
| 产物 | `parsed.json` 包含识别类型、解析内容；图片另有尺寸信息，PDF 另有页数和图片清单 |

复用原有限额：输入合计 1 MiB；产物最多 8 个，单个最多 2 MiB、合计最多 4 MiB。PDF 的 7 张图加一个 `parsed.json` 正好是 8 个。默认图片最长边上限 2048，可通过 `max_long_edge` 调低到 64–2048；PDF 最高按 144 DPI 渲染，并继续受最长边限制。复杂页面可能仍超过输出额度，此时降低尺寸后重新提交。文件内容只在沙箱中解析，管理服务不解析图片/PDF。

## 准备

```bash
cd /Users/wx/LazyX/sandbox_smokescreen
docker compose up --build -d --wait --wait-timeout 1800
python3 -m venv .venv
.venv/bin/python -m pip install -r examples/requirements.txt
```

`examples/call.py` 是独立调用方，直接访问 `localhost:18443`，不调用 Docker、不导入 OpenSandbox 或测试设施。只需 gRPC 依赖和协议源文件；协议消息代码生成到临时目录，用完删除。使用其他内网服务地址时，在命令中加 `--address <服务内网IP>:18443`。服务默认仅发布到本机，跨机器调用需在部署时配置 `SANDBOX_BIND_IP`。

## 人工逐项验收

```bash
# 基本执行：返回 success；stdout 的计算值 5 写入报告
.venv/bin/python examples/call.py python

# 图片规范化：输出 PNG，方向校正后尺寸为 128 × 256，无 EXIF
.venv/bin/python examples/call.py parse tests/fixtures/photo.jpg --max-long-edge 256

# PDF 转图：输出两张 480 × 240 的 PNG（144 DPI），第一张红色、第二张蓝色
.venv/bin/python examples/call.py parse tests/fixtures/two-pages.pdf --pdf-images --max-long-edge 512

# 只提取 PDF 文字：不指定 --pdf-images，保持旧行为
.venv/bin/python examples/call.py parse tests/fixtures/two-pages.pdf

# 下面两条预期失败、命令退出码为 1；查看报告中的具体原因
.venv/bin/python examples/call.py parse tests/fixtures/fake.pdf
.venv/bin/python examples/call.py parse tests/fixtures/too-many-pages.pdf --pdf-images

# 运行中取消：返回 cancelled，资源清理完成
.venv/bin/python examples/call.py cancel

# 分段执行：两个不同任务，最终合计 106.0
.venv/bin/python examples/call.py staged
```

每次结果保存在相邻目录 `../sandbox_smokescreen_outputs/external/<用例-随机编号>/`：

- `report.json`：任务编号、状态、错误、stdout/stderr、产物摘要。
- `artifacts/`：校验 SHA-256 后保存的产物。
- 分段示例分为 `step-1/`、`step-2/`。

正常返回会显示“清理完成”和“已确认接收”。失败样例也会保存报告并确认接收；不能把预期拒绝当成服务故障。结果正文在服务内只保留 180 秒，调用方应及时保存后调用 `Acknowledge`。这些样例结果是调用方保存的文件，不是沙箱宿主落盘任务数据。

## Agent 怎么调用

以 `src/sandbox_model/proto/sandbox.proto` 为契约。先检查 `Ready`，再 `Submit → Status → Result → Acknowledge`，用户停止时调用 `Cancel`。新任务使用新 UUID；同编号重试必须保持请求内容一致。仅看到连接断开不代表任务已取消，需查询原编号。

文件任务使用 `kind="parse"`、`environment="files"`，通过 `inputs` 传一个文件及其 SHA-256。可选字段：

```python
request.parse_options.CopyFrom(pb.ParseOptions(
    pdf_images=True,    # 仅适用于 PDF；不填时保留只提取文字的行为
    max_pages=7,        # PDF 转图页数上限，1–7；超过就失败
    max_long_edge=1024, # 最长边像素，64–2048
))
```

`max_pages=0` 使用默认 7；`max_long_edge=0` 使用默认 2048。非 PDF 图片不填写 `pdf_images`、`max_pages`。超出参数范围在提交时返回 `INVALID_PARSE_OPTIONS`；文件损坏、类型不符和转换超限返回 `EXECUTION_FAILED`，报告保留具体错误原因。

分段示例中，第一段把调用需求和中间结果写到 `next.json`，本次沙箱结束；调用方检查操作和参数，再模拟取得税率 0.06；第二段在新沙箱中接收中间数据和税率，计算出 106.0。这里的税率是合成业务返回值，没有真实 Key、没有调用收费服务。真实产品在调用方这一步接入自己的 API。请求产物是待检查的输入，不能直接当命令执行。脚本必须主动保存检查点，不支持任意进程暂停和恢复。

## 自动验证

```bash
python3 scripts/run.py --files
```

此命令重建节点，执行模块测试及文件能力专项验收，结束后恢复正常模式。完整回归仍用 `python3 scripts/run.py`，会执行故障和动态缓存清理测试，运行期间不要让其他调用方提交任务。报告保存在代码目录外。

Mac 验收期间需保持机器唤醒，避免合盖。宿主睡眠会暂停 Docker Desktop，并触发沙箱的超时和失联清理；这种中断不算验收通过。

图像解码使用 [Pillow](https://pillow.readthedocs.io/en/stable/reference/Image.html)，PDF 渲染使用 [pypdfium2/PDFium](https://pypdfium2.readthedocs.io/en/stable/python_api.html)，版本固定在构建文件；依赖升级后需要重新验收。
