# SB3 自动环境准备与人工验收

SB3 在现有独立沙箱服务上增加公共依赖自动准备。Agent 提交依赖声明，服务安装、封装和复用环境；真实产品授权、模型与连接器仍属于 SB4。

## 支持范围

- Python 3.12：依赖写成 `requests==2.32.3`，使用 PyPI；支持 wheel，以及固定 setuptools/wheel/C/C++ 工具模板能编译的源码包。
- Node.js 22：依赖写成 `esbuild@0.25.0`，使用 npm 公共仓库；支持安装脚本、CommonJS 与 ESM。
- 最多 32 个直接依赖、256 个解析依赖。必须指定精确版本；暂不接收版本范围、私有包源、Git/URL、本地包或自定义 Dockerfile。
- 浏览器、字体和系统库继续由固定平台模板提供。需要 Rust、额外系统库或模板未提供的构建后端时，明确失败，不在节点临时开放权限。
- 每个构建最多 300 秒、1 CPU、1 GiB 内存；单构建并发。下载流量最多 128 MiB，依赖目录最多 256 MiB，最终导出最多 128 MiB。构建与普通执行分别排队，普通任务保持原有限额。

## 怎样准备环境

1. 验证任务字段和依赖声明，查询已登记环境。
2. 新组合在独立 gVisor 构建容器中解析并锁定完整依赖，安装或编译。安装使用非特权 UID 1000，没有任务代码、输入文件、密钥、Docker socket 或业务工具通道。
3. 停止安装进程，撤销网络，导出依赖目录。可信侧检查路径、链接、文件类型、数量与大小。
4. 固定 Dockerfile 只执行 `FROM/COPY/LABEL`，将公共依赖封装进基础镜像；不会在可信节点执行第三方安装脚本。
5. 在新的 gVisor 容器验证解释器，清理构建资源后登记镜像。任务再通过 OpenSandbox 创建新的执行沙箱，才接收代码和文件。

镜像封装使用当前固定 Docker 29.1.3 的经典构建器，不依赖额外 BuildKit 缓存服务。升级 Docker 时需要回归该路径。功能测试和哈希校验不等于对第三方包做了全面安全认证。

构建网络只允许 PyPI、Python 文件源和 npm 仓库。构建专用 Smokescreen 使用固定的 `https://1.1.1.1/dns-query`，验证服务器证书并拒绝重定向；避免本机 DNS 返回 `198.18.x.x` 导致下载被拦。解析失败即失败。正常模式的普通任务也默认使用此受控 DoH 端点；域名与私网限制保持不变。

## 缓存行为

- 镜像由节点内 Docker 管理，保存在项目的 `docker-data` 卷；索引和公共依赖锁文件保存在 `state` 卷。代码目录不保存镜像或运行报告。
- 环境由基础镜像、构建模板镜像、架构、语言和完整依赖锁共同识别。请求清单的索引用于找到已锁定的环境，不会每次重新解析最新版本。
- 相同环境的并发请求共享一次构建。取消一个等待者不影响其他等待者；最后一个等待者取消时结束构建。
- 镜像丢失时按保存的原锁文件重建；包不可取得、校验值不符或锁文件损坏时失败。
- 最多缓存 8 个环境，动态依赖文件总量最多 512 MiB，固定基础镜像另计。按最近使用时间清理镜像，正在使用或等待的环境不会被清理。清理镜像保留原依赖锁，避免以后重建时升级间接依赖；最多保留 128 个锁定组合，达到上限时明确拒绝新增组合。
- 每个任务始终创建新容器。用户代码、Skill 包、输入和输出不会进入共享镜像。

## 人工逐项验收

在项目目录运行，首次启动需要联网：

```bash
cd /Users/wx/LazyX/sandbox_smokescreen
docker compose up --build -d
```

`docker compose ps` 显示 `healthy` 后逐条执行：

| 命令 | 应观察到的结果 |
|---|---|
| `python3 scripts/demo.py deps-python` | 自动准备 requests，返回版本 2.32.3，显示环境编号和缓存是否命中 |
| 再执行上一条命令 | 相同环境编号，显示“缓存命中：是” |
| `python3 scripts/demo.py deps-node` | esbuild 安装脚本与二进制可用，ESM 求和为 5，TypeScript 转换成功 |
| `python3 scripts/demo.py deps-source` | netifaces 源码 C 扩展编译成功，并在新的执行沙箱中调用成功 |
| `python3 scripts/demo.py python` | 原有固定环境命令仍返回计算结果 5 |

如果环境已被自动验收准备好，第一次人工运行也会命中缓存，这是正常结果。首次未缓存构建与缓存复用的强制验证由下面的完整验收覆盖。

人工报告和产物在相邻的 `sandbox_smokescreen_outputs/manual/<案例>/`。报告中的 `environment_id` 标识完整锁定环境，`environment_cache_hit` 表示是否直接复用。它不是 Docker 镜像内容摘要；镜像缺失后重新封装，环境编号保持一致，Docker 镜像 ID 可能变化。

查看中文阶段日志：

```bash
docker compose exec sandbox tail -f /run/sandbox_model/service.log
```

最近一次公共依赖安装的原始诊断仅在节点 RAM 的 `/run/sandbox_model/build-last.log` 保留，最多 32 KiB，不复制进普通服务日志或报告；重建节点后消失。

## 完整自动验收

```bash
python3 scripts/run.py
```

包含 SB0–SB2 回归和 SB3 的真实包源下载、编译、并发共享、取消、版本冲突、重复提交冲突、重建与重启缓存检查。会清理本项目的动态公共环境缓存、执行故障测试并重启服务；运行时不要同时提交其他任务。结束后恢复服务，并把报告保存到相邻的 `sandbox_smokescreen_outputs/compose-<时间>/`。

当前验证目标仍是本机 ARM64 Docker Desktop。AMD64、阿里云目标机型及真实产品接入需另外验收。
